# Play on TV Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a parent-enabled device send a movie/episode to a TV (via Home Assistant → Rivulet deep link) instead of playing it on the device.

**Architecture:** A new server module `tv.js` holds all Home Assistant logic (config, deep-link building, wake → play, state, play/pause) behind an injectable `fetch`, so it is unit-tested with `node:test`. `server.js` adds four thin routes. The client adds a per-device target store (`src/tvTarget.js`, mirrors `quality.js`), a "Play on" choice in Settings, a header pill, a branch in `playItem`, and a small now-playing bar.

**Tech Stack:** Node 20+ (Express 5, ES modules, native `fetch`, built-in `node:test`), React 19 + Vite, inline style objects.

**Spec:** `docs/superpowers/specs/2026-11-19-play-on-tv-design.md`

## Global Constraints

- Public repo: generic names/placeholders only in code, docs, examples, commit messages. No real IPs, entity ids, tokens, names.
- Feature is off unless `TV_HA_URL`, `TV_HA_TOKEN` and `TV_HA_ENTITY` are all set; then nothing changes for any install that hasn't configured it.
- The HA token never reaches the browser (not in `/api/config`, not in errors, not in logs).
- No new runtime dependencies. Tests use built-in `node:test` (`"test": "node --test"`).
- Env vars: `TV_HA_URL`, `TV_HA_TOKEN`, `TV_HA_ENTITY`, `TV_NAME` (default `"TV"`), `TV_URL_TEMPLATE` (default `rivulet://play?ratingKey={ratingKey}&offset={offsetMs}`).
- Kids' devices default to on-device playback; only a device where Settings (PIN-guarded) chose the TV can send to it.
- Version: v3.12.0 (bump `PlexKidsLogo.jsx`, CLAUDE.md version table, CHANGELOG.md).

## Review Focus

1. TV asleep and slow to wake (or never wakes) → user sees "TV didn't wake up", no hang past ~10 s. Test in Task 1.
2. HA unreachable or token rejected (401) → readable error ("Couldn't reach Home Assistant" / "Home Assistant rejected the token"), server doesn't crash, token not in message. Test in Task 1.
3. Item never started or already finished (no `viewOffset`) → `offset` is 0, not `NaN`/`undefined`. Test in Task 1.
4. Non-numeric or crafted `:key` (`123&x=1`, `../`) → 400, nothing sent to HA. Test in Task 1 (`isValidRatingKey`) + curl in Task 2.
5. Device allowed + targeting the TV, but the server later has the feature off → device silently plays on-device again, no pill. Test in Task 3 (`effectiveTarget`).

### Task 1: `tv.js` — Home Assistant TV client (server, unit-tested)

**Files:**
- Create: `tv.js`
- Create: `test/tv.test.js`
- Modify: `package.json` (add `"test": "node --test"`)

**Interfaces:**
- Produces (all named exports of `tv.js`):
  - `loadTvConfig(env: object) -> { enabled: boolean, name: string, haUrl, token, entity, template }` — `enabled` only when url+token+entity are non-empty; `haUrl` without trailing slash; defaults for `name`/`template` per Global Constraints.
  - `isValidRatingKey(key: string) -> boolean` — `/^\d+$/`.
  - `buildTvUrl(template: string, { ratingKey: string, offsetMs?: number }) -> string` — replaces `{ratingKey}` and `{offsetMs}`; `offsetMs` missing/negative/non-finite → `0`, otherwise `Math.floor`.
  - `createTvClient(config, { fetch = globalThis.fetch, sleep = ms => new Promise(r => setTimeout(r, ms)), wakeTimeoutMs = 10000, pollMs = 1000 } = {})` returning:
    - `getState() -> Promise<{ state: string, title: string|null, app: string|null }>` (from HA `GET /api/states/<entity>`: `state`, `attributes.media_title`, `attributes.app_name`)
    - `playOnTv({ ratingKey, offsetMs }) -> Promise<{ url: string }>`
    - `playPause() -> Promise<void>`
  - `TvError extends Error` with `.userMessage: string` and `.status: number` (HTTP status the route should send).
- HA calls: `POST <haUrl>/api/services/media_player/<service>` with JSON `{ entity_id, ... }` and header `Authorization: Bearer <token>`. Services: `turn_on`, `play_media` (`media_content_type: "url"`, `media_content_id: <url>`), `media_play_pause`.

- [ ] **Step 1: Write the failing tests** in `test/tv.test.js` using `node:test` + `node:assert/strict` and a fake `fetch` that records calls and returns scripted responses. Required tests:
  - `loadTvConfig` → `enabled:false` when any of the three vars is missing/empty; `enabled:true`, `name:"TV"`, default template when all three set; trailing slash stripped from `TV_HA_URL`.
  - `isValidRatingKey`: `"18419"` true; `""`, `"12a"`, `"123&x=1"`, `"../1"` false.
  - `buildTvUrl(default, { ratingKey:"18419", offsetMs: 600000.7 })` === `"rivulet://play?ratingKey=18419&offset=600000"`; `offsetMs` `undefined` / `-5` / `NaN` → `offset=0`.
  - `playOnTv` when state is `"idle"`: no `turn_on`; exactly one `play_media` with `media_content_id` = built URL and `media_content_type:"url"`.
  - `playOnTv` when state is `"off"`: calls `turn_on`, polls `getState` until not `off`/`standby`, then `play_media`.
  - `playOnTv` when state stays `"off"` past `wakeTimeoutMs` (use `wakeTimeoutMs: 50, pollMs: 10` and a no-op `sleep` that advances a fake clock, or real short timers): rejects `TvError` with `userMessage` "TV didn't wake up" and `status` 504; `play_media` never called.
  - `play_media` fetch throws a network error once then succeeds → resolves (retry once); throws twice → `TvError` "Couldn't reach Home Assistant", status 502.
  - HA returns 401 → `TvError` "Home Assistant rejected the token", status 502, and `userMessage` does not contain the token string.

- [ ] **Step 2: Run tests to verify they fail**
  Run: `npm test`
  Expected: FAIL (cannot find module `../tv.js`).

- [ ] **Step 3: Implement `tv.js`** per the Interfaces block. States that need waking: `off`, `standby`. Retry-once applies to network errors (fetch throws), not HTTP error statuses. Never include the token in any error message or log line.

- [ ] **Step 4: Run tests to verify they pass**
  Run: `npm test`
  Expected: all tests PASS.

### Task 2: Server routes + config docs

**Files:**

- Modify: `docker-compose.example.yml`, `README.md` (new optional "Play on TV" section)

**Interfaces:**
- Consumes: Task 1 exports.
- Produces (HTTP):
  - `GET /api/config` → existing body plus `tv: { enabled: boolean, name: string }`.
  - `POST /api/items/:key/play-on-tv` → `200 { ok: true, title }` | `400 { error }` (no active profile, or invalid key) | `404` (feature off) | `502/504 { error: <TvError.userMessage> }`.
  - `GET /api/tv/state` → `200 { state, title, app }` | `404` (off) | `502 { error }`.
  - `POST /api/tv/playpause` → `200 { ok: true }` | `404` | `502 { error }`.

- [ ] **Step 1: Wire it up.** At startup: `const tvConfig = loadTvConfig(process.env); const tv = tvConfig.enabled ? createTvClient(tvConfig) : null;` and log `TV: <name> (enabled)` or `TV: disabled` (no URL/token in the log). All three TV routes return 404 when `!tv`. `play-on-tv` requires `req.session.user` (400 "No active profile") and `isValidRatingKey(req.params.key)` (400) **before** any Plex/HA call; reads `viewOffset` and `title` (episodes: `"<grandparentTitle> - <title>"`) from `fetchPlexJson('/library/metadata/<key>', activeToken(req))`; calls `tv.playOnTv({ ratingKey, offsetMs: meta.viewOffset })`. `TvError` → its `status` + `userMessage`; any other error → 502 "Couldn't start playback".
- [ ] **Step 2: Docs.** `docker-compose.example.yml`: commented-out block for the five `TV_*` vars with placeholder values and one-line explanations. `README.md`: short "Play on TV (optional)" section: what it does, requirements (Home Assistant with the TV's `media_player`, an app on the TV that handles deep links — Rivulet on Apple TV by default), the env vars, that a device opts in under Settings → Play on, and the Rivulet tip (Profile Picker → Off).
